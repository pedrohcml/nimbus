# Intent labeling guidelines

The router reads only the customer's latest message and picks one intent.
Each intent sends the conversation to a different place.

## Intents

| Intent | use it when the customer |
|---|---|
| `transaction_status` | wants the state or details of a transaction |
| `dispute` | does not recognize a charge, says it is wrong, or asks about an open dispute |
| `refund` | recognizes a charge and wants the money back, or asks about a refund |
| `policy_question` | asks how Nimbus works: fees, times, limits, rules |
| `human` | asks for a person |
| `smalltalk` | greets or thanks without a request |
| `out_of_scope` | asks for something the agent cannot do, or something unrelated |

## Tie-breaking rules

1. Dispute or refund: "it was not me" or "it is wrong" is `dispute`.
"It was me, but I want to undo it" is `refund`.
2. Two requests in one message: label the action the customer wants, not the
context. "tx_123 is late and I want my money back" is `refund`.
3. Messages that only make sense with the conversation ("yes", "that one") are not in the dataset. They never reach the router.
4. The customer's own account state that the agent cannot see (balance,
verification status) is `out_of_scope`. How something works in general
(how verification works) is `policy_question`.

## Sources

- `handwritten`: written by a person, without looking at other examples.
- `eval_v0`: first messages from `evals/datasets/v0.yaml`.
- `generated`: generated by an LLM for training (week 5). Never in the test set.
